# Week 10 — 막상 시작하려니 막막한데?

> **이번 주 목표:** 사양설계서를 손에 쥐고도 느끼는 "그래서 뭐부터 하지?"를 해소한다.  
> Week 10~12는 각자의 프로젝트를 실제로 완성하는 시간이다.

---

## 설계서까지 썼는데, 왜 아직도 막막할까?

지난 주에 사양설계서를 완성했습니다. "무엇을 만들지"는 글로 정의가 됐어요. 그런데 막상 Antigravity를 열면 커서만 깜빡입니다.

이 막막함의 정체는 대부분 셋 중 하나입니다.

**"어디서부터 시작해야 하지?"** — 전체를 한 번에 만들려다 보니 첫 발을 못 뗀다.

**"AI한테 뭐라고 말해야 하지?"** — 사양설계서를 통째로 던지면 될지, 아니면 다르게 말해야 할지 모르겠다.

**"내가 하는 게 맞는지 모르겠다."** — 진행하다가 틀린 방향으로 가고 있을까봐 두렵다.

세 가지 모두 정상적인 반응입니다. 그리고 모두 해결 방법이 있어요.

---

## 원칙 하나: 전부 만들려 하지 말고, 작동하는 것부터

영어로 **MVP**라고 합니다. *Minimum Viable Product* — 최소한으로 작동하는 버전.

비유하자면, 서울에서 부산까지 가야 할 때 처음부터 고속철도를 만들려 하지 않는 거예요. 일단 자전거로라도 방향이 맞는지 확인하고, 그 다음에 오토바이, 자동차, 기차로 업그레이드하는 방식입니다.

**MVP의 기준은 단 하나입니다: 실제로 실행이 되는가.**

오류 없이 실행되고, 의도한 출력이 하나라도 나오면 MVP입니다. 예쁠 필요도, 빠를 필요도, 완벽할 필요도 없어요.

MVP가 나오면 그때부터는 덧붙이는 작업입니다. 처음 시작보다 훨씬 쉬워집니다.

---

## ⚡ 잠깐 — 코딩 시작 전에 스킬부터 설치하세요

> 지금 Antigravity를 열고 싶은 마음, 압니다. 그런데 5분만 투자하면 앞으로 수십 번의 삽질을 막을 수 있어요.

**AI가 자주 저지르는 실수 두 가지가 있습니다.**

하나는 **모델명 오류**입니다. AI는 훈련 당시에 학습한 모델명을 기억에서 꺼내씁니다. 그런데 Gemini, OpenAI 모델은 수시로 업데이트되고 구버전은 shutdown됩니다. 코드를 실행하면 "모델을 찾을 수 없습니다" 오류가 뜨고, 왜 안 되는지 한참을 헤맵니다.

또 하나는 **라이브러리 API 오류**입니다. AI가 기억하는 코드 패턴이 실제 설치된 버전과 다를 때가 있어요. 분명히 AI가 짜준 코드인데 실행하면 바로 에러가 납니다.

**스킬(Skill)은 이 실수를 사전에 차단합니다.** 특정 키워드가 대화에 등장하는 순간 Antigravity가 해당 지침을 자동으로 꺼내 읽고 행동 방식을 바꿉니다. 마치 새 직원에게 "이 상황에서는 반드시 이렇게 해"라고 매뉴얼을 쥐여주는 것과 같아요. 설치는 명령어 하나, 30초면 끝납니다.

**설치 방법**

PowerShell 터미널을 열고 아래 명령어 하나만 실행하세요.

```powershell
npx skills add arimons/skills -g -a antigravity
```

명령어 의미를 간단히 풀면:

- `npx skills` — 스킬 관리 도구를 실행
- `add arimons/skills` — arimons가 만든 스킬 모음을 설치
- `-g` — 이 컴퓨터 전체에 적용 (특정 프로젝트만이 아니라)
- `-a antigravity` — Antigravity 에이전트 전용으로 설치

설치 후 Antigravity를 재시작하면 바로 반영됩니다.

**설치되는 스킬 세 가지**

`grill-me` — 프로젝트 시작 전 설계 인터뷰 스킬. 새 대화에서 `grill me`라고 입력하면 발동됩니다. AI가 프로젝트 설계의 빈틈을 하나씩 짚어주고 인터뷰 형식으로 구체화를 도와줍니다.

`llm-model-reference` — Gemini, OpenAI, Claude API 코드를 작성할 때 자동으로 발동됩니다. AI 모델은 수시로 업데이트되어 예전 모델명이 더 이상 작동하지 않는 경우가 있어요. 이 스킬이 현행 모델명 기준을 강제해서 "모델을 찾을 수 없습니다" 오류를 예방합니다.

`context7-usage` — 외부 라이브러리 코드를 작성할 때 자동으로 발동됩니다. AI가 기억에서 꺼내는 오래된 API 대신, Context7을 통해 현재 공식 문서를 확인하고 코드를 작성하도록 유도합니다.

## 첫 대화를 시작하는 방법

### Step 1. 프로젝트 폴더 먼저 만들기

Antigravity에서 새 프로젝트 폴더를 하나 만드세요.

```
C:\Developer\
└── my-project\        ← 이름은 자유롭게
    └── (아직 비어있음)
```

Antigravity에서 이 폴더를 열면 AI가 이 폴더를 "작업 공간"으로 인식합니다.

---

### Step 2. Grill Me — 사양설계서와 함께 인터뷰받기

사양설계서가 있어도 빈틈은 있습니다. 코딩을 시작하기 전, **같은 대화 안에서** `grill me`와 사양설계서를 함께 던지세요. AI가 설계서를 읽고 결정되지 않은 부분을 하나씩 짚어줍니다.

Antigravity 새 대화창에서 아래 형식으로 입력하세요.

```
grill me

내 사양설계서야:
--- [사양설계서 내용 붙여넣기] ---
```

`grill me`가 명시적으로 있어야 스킬이 발동됩니다. 사양설계서만 던지면 AI가 바로 코드를 만들려 하지만, `grill me`가 있으면 먼저 인터뷰 모드로 전환됩니다.

질문마다 AI가 권장 답변도 함께 제시하니까, "네" 또는 "좋아요"만 해도 대화가 진행됩니다. 인터뷰가 끝나면 AI가 설계 요약을 만들어줍니다. **그 대화를 그대로 이어서** Step 3 코딩 요청을 하면 됩니다. 새 창을 열 필요 없어요.

---

### Step 3. 코딩 요청 — MVP부터 시작

인터뷰가 끝나면 **같은 대화를 그대로 이어서** 코딩을 요청하세요. AI가 방금 인터뷰한 내용을 묶고 있으니 사양설계서를 다시 붙여넣을 필요가 없습니다.

```
위 내용을 바탕으로 MVP부터 단계별로 만들어줘.

조건:
- Python 3.12, Windows 환경
- 가상환경(.venv) 사용
- 라이브러리는 pip 설치 가능한 것으로
- 먼저 파일 하나를 읽어서 결과를 화면에 출력하는 것부터 시작해줘
- 각 단계마다 설명해줘
```

**"파일 하나를 읽어서 결과를 화면에 출력하는 것부터"** — 이것이 MVP입니다. 엑셀 저장, 예쁜 출력, 예외 처리는 그 다음입니다.

---

### Step 4. 에러가 나면 — 당황하지 않는 법

코드를 실행하다 빨간 글씨가 뜨면 멈추지 마세요. 에러 메시지를 전체 복사해서 AI에게 그냥 붙여넣으면 됩니다.

```
아래 에러가 났어. 고쳐줘.

[에러 메시지 전체 붙여넣기]
```

이것만으로 충분합니다. 에러 메시지는 AI에게 가장 정확한 정보이기 때문에, 길어도 전부 붙여넣는 게 좋습니다.

오류 없이 실행되고, 의도한 결과가 하나라도 나오면 성공입니다.

### Week 11 — 실제로 쓸 수 있는 버전으로 다듬기

MVP가 돌아간다면, 이제 현실적으로 쓸 수 있는 수준으로 만들어야 합니다.

모든 기능을 한 번에 추가하려 하지 말고, 하나 추가하고 실행해서 확인한 후 다음으로 넘어가세요.

## 실제 구현 예시

수강생들이 실제로 추진 중인 프로젝트 두 가지를 예시로 정리했습니다. 비슷한 방향이라면 그대로 참고해도 좋고, 다른 주제의 설계 참고용으로도 활용하세요.

---

### 예시 1. COA 문서 → 엑셀 자동완성 (검토 GUI 포함)

**하고 싶은 것:** 보안이 걸린 COA PDF에서 원하는 항목을 뽑아 엑셀 빈칸을 자동으로 채우고 싶다. 단, 완전 자동화가 아니라 AI가 뽑은 값을 내가 한 번 눈으로 확인하고 승인하면 저장되는 구조.

**전체 흐름:**

```
[PDF 파일]
    ↓
이미지로 변환 후 민감 영역 크롭·마스킹
    ↓
LLM (Gemini Vision)
    ↓
JSON Schema 형식으로 값 반환
    ↓
[웹 GUI] — 추출 결과를 화면에 표시, 값 수정 가능
    ↓  (승인 버튼 클릭)
기존 엑셀 파일의 빈칸에 값 기록
```

**왜 중간에 GUI를 넣는가?**

LLM은 완벽하지 않아서 가끔 값을 잘못 읽거나 형식이 미묘하게 틀릴 수 있습니다. 완전 자동화로 엑셀에 바로 쓰면 오류가 쌓여도 모릅니다. GUI에서 JSON 추출 결과를 먼저 보여주고 — 맞으면 그대로 저장, 틀렸으면 수정 후 저장 — 이 중간 단계가 실무에서 신뢰도를 높이는 핵심입니다.

**MVP 시작점:**

```
PDF 파일 하나를 받아서, LLM이 읽은 결과를 JSON으로 터미널에 출력하는 것
```

GUI, 마스킹, 엑셀 저장은 그 다음 단계입니다.

**첫 번째 AI 프롬프트 예시:**

```
COA PDF 파일을 pymupdf로 이미지로 변환한 뒤,
Gemini Vision API로 아래 항목들을 추출하고 JSON으로 반환하는
파이썬 스크립트를 만들어줘.

추출 항목:
- product_name: 제품명
- cas_number: CAS 번호
- purity: 순도 (%)
- moisture: 수분 함량 (%)
- storage: 보관 조건

지금은 결과를 터미널에 출력하는 것까지만 만들어줘.
Python 3.12, Windows 환경, 가상환경(.venv) 사용.
```

**기술 스택:** `pymupdf`, `Pillow`, `google-genai`, `streamlit` (GUI용), `openpyxl`

### 예시 2. PubMed 논문 검색 → 엑셀 수집

**하고 싶은 것:** PubMed에서 특정 검색어로 논문을 찾고, 제목·초록·링크를 엑셀에 쭉 쌓고 싶다. 검색어를 바꿔가며 반복 사용할 수 있게.

**PubMed URL 구조:**

PubMed 검색은 URL의 `term` 파라미터로 검색어를 전달합니다. 단어 사이 공백은 `+`로 연결합니다.

```
https://pubmed.ncbi.nlm.nih.gov/?term=skin+permeation
                                        ↑ 검색어 (공백 → +)
```

검색어를 바꾸고 싶으면 `term=` 뒤 부분만 바꾸면 됩니다. 코드에서는 이렇게 처리할 수 있습니다.

```python
query = "skin permeation"  # 검색어
url = f"https://pubmed.ncbi.nlm.nih.gov/?term={query.replace(' ', '+')}"
```

**전체 흐름:**

```
[검색어 입력] (예: "skin permeation")
    ↓
URL 조립 → requests로 페이지 요청
    ↓
BeautifulSoup으로 논문 목록 파싱
(제목, 저자, 저널, 연도, PMID, 초록)
    ↓
각 논문 상세 페이지에서 추가 정보 수집 (필요 시)
    ↓
openpyxl로 엑셀에 한 행씩 기록
```

**수집할 항목:**

| 컬럼 | 설명 | 예시 |
|------|------|------|
| 제목 | 논문 제목 | Skin permeation enhancement by... |
| 저자 | 제1저자 외 | Kim J, et al. |
| 저널 | 게재지 | Int J Pharm |
| 연도 | 출판연도 | 2024 |
| PMID | PubMed 고유번호 | 38472819 |
| 초록 | Abstract 전문 | ... |
| 링크 | 논문 URL | https://pubmed.ncbi.nlm.nih.gov/38472819/ |

**MVP 시작점:**

```
검색어 하나를 받아서, 첫 페이지 논문 목록의 제목과 링크를 터미널에 출력하는 것
```

여러 페이지 수집, 초록 전문, 엑셀 저장은 그 다음 단계입니다.

**첫 번째 AI 프롬프트 예시:**

```
PubMed에서 검색어를 입력받아 논문 목록을 스크래핑하는
파이썬 스크립트를 만들어줘.

PubMed 검색 URL 구조:
https://pubmed.ncbi.nlm.nih.gov/?term=검색어 (공백은 +로 연결)

수집할 항목: 논문 제목, PMID, 링크
결과는 지금은 터미널에 출력만 해줘.

라이브러리는 requests, beautifulsoup4 사용.
Python 3.12, Windows, 가상환경(.venv).

먼저 HTML 구조를 파악해야 하니, 실제 URL을 요청해서
어떤 태그에 논문 목록이 있는지부터 확인해줘.
```

**기술 스택:** `requests`, `beautifulsoup4`, `openpyxl`

> **주의:** 스크래핑 전에 반드시 대상 사이트의 이용약관을 확인하세요. PubMed는 공공 데이터베이스이며 연구 목적 수집은 허용되나, 과도한 요청(초당 여러 번)은 IP 차단으로 이어질 수 있습니다. 요청 사이에 `time.sleep(1)` 정도 여유를 두세요.

## 자주 막히는 순간과 해결법

### "어디까지 AI에게 맡겨야 하나요?"

기준은 간단합니다. 코드를 이해하지 못해도 됩니다. 결과를 판단할 수 있으면 됩니다.

AI가 만들어준 코드가 의도한 대로 실행되는지 확인하는 것, 출력된 결과가 맞는지 검토하는 것이 여러분의 역할입니다. 코드 한 줄 한 줄을 설명할 수 없어도 괜찮습니다.

---

### "AI가 엉뚱한 걸 만들어왔어요."

두 가지 원인 중 하나입니다.

사양설계서의 설명이 부족했거나, 아니면 AI에게 전달한 내용이 불충분했거나. 이럴 때는 AI에게 이렇게 말하면 됩니다.

```
내가 원한 건 이게 아니야.
내가 원하는 건 [구체적으로]인데, 지금 만든 것은 [어떤 문제]가 있어.
다시 만들어줘.
```

AI는 틀려도 됩니다. 틀린 걸 정확히 지적해주면 금방 고칩니다.

---

### "코드가 중간에 멈춰요 / 에러가 계속 나요."

에러 메시지를 전체 복사해서 AI에게 보내세요. 그것만으로 충분합니다.

해결이 안 되면, 채팅창을 새로 열고 이렇게 시작해보세요.

```
아래 코드가 있는데, [증상]이 발생해.
에러 메시지는 이거야: [에러 전체 붙여넣기]
무엇이 문제인지 설명하고 고쳐줘.

[코드 전체 붙여넣기]
```

새 채팅창에서 코드 전체를 다시 붙여넣는 게 핵심입니다. AI는 이전 대화를 기억하지 못하기 때문에, 같은 대화창이 너무 길어지면 앞 내용을 잊어버리는 경우가 있어요.
